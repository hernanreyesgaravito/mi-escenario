¿Qué es VSF (Virtual Switching Framework)?

VSF permite combinar múltiples switches físicos Aruba para operar como un único switch lógico. Aunque físicamente existen varios equipos, ArubaOS los administra como un único chasis virtual.

Explicación Técnica

  • 🧠 Commander: Mantiene el plano de control, protocolos y configuración.
  • 🛡️ Standby: Permanece sincronizado y asume control si el Commander falla.
  • ⚡ Members: Participan en forwarding pero se administran desde una sola CLI.
  • 🔄 VSF Links: Son enlaces internos dedicados para sincronización.
  • 📦 Chasis Virtual: Todo opera como un único equipo lógico.

Analogía Técnica

Piensa en un avión:

  • ✈️ Piloto → Commander
  • ✈️ Copiloto → Standby
  • ✈️ Tripulación → Members
  • 📡 Comunicación interna → VSF Links
  • 🛫 Todo el avión → Stack VSF

Consideraciones antes de armar el Stacking (VSF)

Antes de conectar cualquier cable o ejecutar comandos, asegúrate de tener en cuenta estas reglas:


  • 🔌 Libres de conexiones: No es obligatorio pero sí recomendable inicialmente. Lo principal es dejar libres los puertos que se van a usar exclusivamente para armar el stack (los uplinks de VSF).
  • ⚙️ Estado de Fábrica: Recomendable que ambos switches (excepto el que programarás como jefe) estén de fábrica (erase-all o erase all zeroize).
  • 🔄 Firmware: Recomendable que todos los miembros del stack tengan exactamente la misma versión de software. No es obligatorio pero sí es recomendable.
  • 🧩 Mezcla de Modelos: En la serie 2930F, puedes mezclar modelos (ej. puedes unir uno de 24 puertos con uno de 48 puertos sin problema).
  • 🆔 Dominio VSF: Todos los miembros de un mismo stack deben tener el mismo domain ID para reconocerse.
  • ⭕ Topología Chain vs Ring: Cuando tienes 2 switches, usas topología de Cadena (Chain). Si tienes 3 o más switches, es obligatorio cerrar el ciclo físicamente creando una topología de Anillo (Ring) usando link 1 y link 2.

1. ¿Qué es el VSF Domain? (vsf enable domain 1)

Antes de conectar cables o asignar prioridades, el paso CERO es habilitar el framework y crear el clúster con vsf enable domain <ID>.

  • 🌐 Identidad del Stack: Este Domain ID (del 1 al 4294967295) agrupa lógicamente a los switches. Todos los equipos físicos deben tener configurado exactamente el mismo Domain ID.
  • 🛡️ Aislamiento (La Analogía del Uniforme): Piensa en el Domain ID como el "Uniforme de un equipo". Imagina que tienes el equipo Rojo (Domain 1) y el Azul (Domain 2). Si por error alguien conecta un cable entre un jugador Rojo y uno Azul, no se fusionarán. Al ver que sus "uniformes" no coinciden, evitan un desastre y no forman el enlace VSF.

2. Alta Disponibilidad: ¿Qué pasa si el SW1 falla?

La magia del VSF es la resiliencia y su comportamiento ante fallos eléctricos o desconexiones totales:

  • ⚡ Failover Inmediato: Si el Switch 1 (Commander) muere, pierde comunicación con todos. Tanto el SW2 como el SW3 quedan aislados del SW1, pero el SW2 (Standby) asume inmediatamente el rol de Commander. La IP de gestión y el routing siguen funcionando sin interrupción.
  • 🔄 Anillo a Cadena: Como el SW1 ya no está, el anillo se rompe. Sin embargo, el clúster sobrevive porque el enlace entre el SW2 y SW3 sigue activo, convirtiendo la topología temporalmente en una "Cadena".
  • 👑 No hay "Golpe de Estado" (Sin Preemption): ¿Qué ocurre cuando el SW1 vuelve a encender? NO retoma el control automáticamente. Aunque el SW1 tenga prioridad 255 y el SW2 tenga 200, en Aruba VSF no hay preemption. El SW1 se reincorpora humildemente como Standby o Miembro para evitar causar otra interrupción de red (flapping). Solo volverá a ser Commander si el SW2 falla o si reinicias todo el stack manualmente.

3. Reglas de Oro: Prioridad y Enlaces Lógicos

Para garantizar esta estabilidad, asegúrate de aplicar estas reglas:

  • 🏆 Prioridad: Por defecto es 128. Configurar manualmente las prioridades (ej. 255 para SW1, 200 para SW2) asegura quiénes serán los equipos principales.
  • 🔗 VSF Link 1 vs VSF Link 2:
    • 2 Switches: 2 cables físicos por Link lógico (LACP de 2 hilos). Conexión cruzada recomendada.
    • 3 o más Switches: 1 cable físico por Link. Conexión cruzada estrictamente obligatoria (L1 ↔ L2) para formar el anillo.

4. Comandos de Validación y Mantenimiento

Otros comandos importantes para la administración del día a día del chasis lógico:


  • 🔄 redundancy switchover - Obliga al Commander actual a reiniciarse para que el Standby tome el control de inmediato.
  • 🗑️ vsf member [ID] remove (o stacking member [ID] remove) - Esto hace tres cosas:
    1. Borra la configuración de ese miembro en el stack.
    2. Apaga el switch remoto de forma segura.
    3. Limpia la base de datos para que el stack no lo eche de menos y no marque alertas.
  • ⚡ boot vsf member [ID] - Reinicia un miembro específico del stack sin impactar a los demás equipos.
